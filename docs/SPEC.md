# Type Rush — MVP仕様書

## 1. コンセプト
「一字一句正確に打つ」よりも、「多少の誤字を気にせず、とにかく速く伝える」ことを楽しむブラウザ向けタイピングゲーム。

初期版は**AI・外部APIを使用しない**。文字列の近さを暫定的なクリア基準とする。**意味を理解できるかどうかの判定ではない**ため、AI導入後の判定とは区別する。

## 2. 対象・技術
- PCのデスクトップブラウザを第一対象（スマートフォン表示はレスポンシブ対応、操作検証は後続）。
- React + TypeScript + Vite。スタイルはTailwind CSSを推奨。
- バックエンド・認証・DB不要。問題文はローカルのJSON/TSデータ。
- ローカル記録はlocalStorage。外部通信なしでもプレイ可能な設計。
- 静的サイトとしてデプロイ可能（Cloudflare Pages / GitHub Pages 等）。

## 3. ゲームフロー
1. スタート画面に「スタート」と遊び方を表示。
2. スタートで1問目を表示。入力欄に自動フォーカス。
3. **最初の実際の入力**で計測開始（IMEの未確定入力を含めない）。
4. お題を見ながら自由に入力。誤字があっても入力を止めない。
5. Enterで確定。判定合格なら次の問題へ。不合格ならその場で入力を修正して再提出可能。
6. 既定5問をすべてクリアしたら結果画面へ。再挑戦できる。

## 4. 初期の問題文
- MVPでは**ひらがなのみ**で統一した短文（例：「きょうはてんきがいいのでさんぽにいく」）。
- 問題文と入力をそのまま比較できることを優先。漢字・表記揺れ・意味的言い換えの解釈は将来対応。
- 20〜40文字程度を中心に、最低20問を用意。1ゲーム内の重複を防ぐ。
- 句読点・空白は出題しない（意図的な省略の扱いを曖昧にしない）。
- IME入力確定時に判定する。変換中のEnterはゲーム確定として扱わない。

## 5. クリア判定（暫定ルール）
- Unicode正規化（NFKC）と前後空白除去を行う。入力の内部空白は削除しない。
- Levenshtein距離 d、正解長 n、入力長 m とし、
  `similarity = 1 - d / max(n,m)` （空文字の場合0）。
- **similarity >= 0.85** かつ **入力長 >= 正解長の80%** をクリア条件とする。
- ただし**否定、数値、固有名詞を意味的に正しく認識できるわけではない**。初期問題はそれらの誤認が重大になる文を避ける。
- 判定不合格時は一致率と「もう少し入力してみよう」を表示し、計測を継続。
- 正解入力を強制せず、編集距離由来の近似判定で進行させる。基準値は設定定数に切り出す。

## 6. 計測・スコア
- `performance.now()` で開始から最終問題クリアまでの実時間を計測。
- 速度指標は、**確定した入力文字数合計 / 実時間(秒)** を文字/秒および文字/分で表示（ローマ字キー打鍵数ではない）。
- 問題ごとの最終提出について一致率を保存し、平均一致率を表示。
- 最重要の競争指標は**5問クリアまでの総時間（短いほど良い）**。不合格の再提出・修正時間も総時間に含める。
- スコアはMVPでは複雑な係数を導入せず、総時間・速度・平均一致率を表示する。
- 途中離脱・リロードは未完了として記録対象外。
- ベストタイムをlocalStorageに保存（同じ問題セット・ルールで比較できるよう、ルールバージョンを記録）。

## 7. UX
- キーボードだけで開始・入力・確定・再挑戦まで操作可能。
- 画面は「お題」「入力欄」「現在の問数」「経過時間」を大きく見せる。
- タイプミスのたびに入力を赤く点滅させたり、入力をブロックしたりしない。
- Enterでの判定は即時。画面遷移・アニメーションは最小限。
- IME変換中、連続Enter、未入力Enter、画面外フォーカスを考慮。
- コピー＆ペーストによる入力はゲーム性を損なうためMVPでは貼り付けを拒否し、説明を表示。
- 音・振動・派手な演出は初期版では不要。モバイル端末でのIME/仮想キーボードは後で実機検証。

## 8. 状態設計
`idle -> playing -> result` を基本状態とする。問題ごとに `input`, `attempts`, `acceptedInput`, `similarity` を保持する。

## 9. テスト/受け入れ条件
- 85%以上かつ80%以上の境界ケースで合否が正しい。
- 空文字・完全一致・不足入力・余分入力・1文字置換のテストがある。
- IME composition中のEnterでは提出されない。
- 最初の確定入力以前はタイマーが進まない。
- 不合格の修正時間を含み、5問クリア後はタイマー停止。
- リロードでゲームが初期化され、過去ベストは保持される。
- 問題の重複がなく、貼り付けで不正に進行できない。
- キーボード主体でプレイでき、画面幅が狭くてもUIが崩れない。

## 10. MVP対象外
- LLMによる意味判定、言い換えの理解
- アカウント・オンラインランキング・サーバー
- リアルタイムAI判定、音声入力
- 漢字混じり出題・ローマ字打鍵数計測・難易度別ランキング

## 11. 将来の拡張
- `Judge` インターフェースを抽象化し、`SimilarityJudge` から `AIJudge` に差し替えられる構造。
- 意味を保った省略を競う「高速伝達モード」。
- 同一問題セット/ルールのシード固定による公正な比較。
- 漢字・かな混在問題、スマホ向け最適化、ローカル統計。
