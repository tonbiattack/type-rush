# 桜井政博のゲーム制作の原則で見た Type Rush

`~/.agents/skills/sakurai` の原則を、このゲームに当てて点検した記録です。
「どの原則に反しているか → どう直したか」をセットで残します。
原則は桜井氏のアクション寄りの大作の経験に基づくため、タイピングゲームに読み替えた上で使っています。

## 直したところ

### 1. リトライは迅速に（第2章）

**反していた原則**: 「やられてから操作が戻るまでの間に急速に冷める。ペナルティの重さより再開の速さが効く」

**現状**: 結果画面から「同じ5問でもう一度」を押すと、初回と同じ 3・2・1 のカウントダウン
（2.5 秒）が毎回入っていた。同じ問題をもう一度打つだけなのに、毎回待たされていた。

**直したこと**: 再挑戦は `CountdownMode = 'retry'` にして、数字を出さず「スタート」だけを
0.4 秒出して始めるようにした（`src/game/countdown.ts`）。初回だけ 3・2・1 を出す。
待ち時間が 2.5 秒 → 0.4 秒になり、結果を見てから打ち始めるまでが短くなった。

**副作用**: なし。計測は「最初の確定入力」から始まるので、カウントダウンの長さはスコアに影響しない。

### 2. 褒める演出を入れる（第3章）

**反していた原則**: 「褒める演出を入れる。撃墜の歓声、クリアの拍手」

**現状**: 合格すると問題が切り替わるだけで、何も返ってこなかった。不合格のときだけ判子が出ていた。
つまり**失敗にだけ反応し、成功には無反応**だった。

**直したこと**: 合格時に次の問題へ「合格」の判子を出し、その問題の所要時間を添えるようにした
（`src/game/engine.ts` の `feedback.kind = 'accepted'`）。打ち始めると消えるので、次の問題を
打つ手を止めない。不合格の判子は直すための案内なので、入力しても残す。

**副作用**: 判子のモーションは既存の 1 箇所（`.stamp`）を使い回すので、AGENTS.md の
「動きは判定の判子 1 箇所だけ」を守っている。`prefers-reduced-motion` も既存のままで効く。

### 3. 目標は目の前に吊るす（第3章）

**反していた原則**: 「目標は目の前に吊るす（次のレベルまであと○、少し貯めれば買える装備）」

**現状**: スタート画面の称号一覧は 7 段を並べただけの表で、自分がどこにいるか分からなかった。
現在地は結果画面にしか出ず、スタート画面に戻ると消えていた。

**直したこと**: スタート画面の称号一覧で、自己ベストの段を墨で塗って現在地を示すようにした
（`src/components/RankLadder.tsx`）。記録が無いときは「1回遊ぶと、いまの位置がここに出ます」と案内する。

**副作用**: 記録が無い初回は塗りがないので、見た目は従来と同じ。

### 4. ダメ出しは改善案とセットで（第12章）

**反していた原則**: 「ダメ出しは改善案とセットに。思ったことはすぐ言う」

**現状**: 不合格のとき「一致率 92.3%」とだけ出していた。92% なのに落ちた理由
（長さが足りないのか、文字が違うのか）が分からず、次に何をすればよいか判断できなかった。

**直したこと**: 判定の `reason`（`too-short` / `low-similarity`）を `feedback` に載せ、
「まだ短い。お題の最後まで打ってから Enter。」「文字が違う。お題と見比べて直してから Enter。」
と、次にやることを返すようにした（`src/screens/PlayScreen.tsx`）。

**副作用**: 判定ルール自体は変えていないので `RULES_VERSION` は据え置き。自己ベストの比較条件は変わらない。

### 5. スコアは見せ方で化ける（第3章）

**反していた原則**: 「スコアは見せ方で化ける（脳年齢、被害総額、世界戦闘力など現実の尺度に置き換える）」

**現状**: 結果画面は総時間と平均一致率だけで、どこで時間を使ったのか分からなかった。
総時間だけを見せられても、次の1回で何を直せばよいか決められない。

**直したこと**: 問題ごとの所要時間を記録し（`ProblemResult.durationMs`）、結果画面の表に
「時間」列を足した。加えて「いちばん時間がかかったのは 2問目（2.64秒）。」と名指しする。

**副作用**: `ProblemResult` に必須フィールドが増えたが、保存形式（localStorage）は変えていないので
既存の記録はそのまま読める。

## やらないと決めたこと

| 案 | やらない理由 |
| --- | --- |
| 音・効果音を足す | AGENTS.md と SPEC が MVP のスコープ外と明記している。追加するとビルドサイズと検証範囲が増える |
| 画面振動・フラッシュ | 同上。加えて「動きは判定の判子 1 箇所だけ」に反する |
| 判定ルール（85%・長さ80%）の変更 | 変えると `RULES_VERSION` を上げる必要があり、既存の自己ベストが全部無効になる。今回は手応えではなく「返し方」の問題だったので触らない |
| 称号の追加・改名 | 既に 7 段あり、テストも名前を固定している。段を増やすと閾値の根拠が薄くなる |
| スタート画面の説明文の削減 | 初見でルールが分からないと詰む。ただし「遊び方」は 5 項目に収め、これ以上は足さない |
| スコアに誤字ペナルティ | このゲームのコンセプト（速く伝える）に反する。桜井氏の「気持ちよさには反対の要素を混ぜる」は、ここでは「不合格の再提出時間が総時間に入る」で既に効いている |

## 未確認点

- 実機のスマートフォン（iOS Safari / Android Chrome）での IME 挙動は未検証。今回の変更は
  カウントダウンと表示だけなので影響は小さいと考えるが、確認はしていない。
- 効果音や振動を入れる場合の優先順位（桜井氏の第10章）は、入れる段になったときに改めて設計する。
